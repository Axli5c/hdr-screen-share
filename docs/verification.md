# Проверка прототипа HDR Screen Share

Дата: 17 октября 2026. Windows x64, Python 3.12.14, hdrcapture 0.3.0, PySide6 Essentials 6.12.0.

## Подтверждено

- Установлен готовый CPython 3.12 Windows wheel hdrcapture из GitHub Releases, SHA-256 проверен pip.
- Обнаружены два монитора 2560×1440: основной HDR (Odyssey G50SF), дополнительный SDR (Mi monitor). Windows HDR-статус согласуется с backend.is_hdr при реальном захвате обоих экранов.
- HDR-источник возвращает SDR BGRA8. Приложение автоматически выбирает HDR-источник, окно-копия выводится на другом мониторе.
- Короткая нативная проверка: 460 новых захваченных и 460 отрисованных кадров примерно за 8 секунд, последняя секундная частота 60.0 FPS.
- Измерение исходной версии за 64.766 секунды: 3705 захваченных кадров, 3702 отрисованных; средние частоты 57.21 / 57.16 FPS. CPU-время процесса 31.34 секунды. Это не подтверждает устойчивые 60 FPS; секундный счётчик временами показывал 60.
- На искусственных красном/зелёном кадрах Windows Graphics Capture получает изменение содержимого окна. Проверка повторена с полным перекрытием окна-копии другим окном: содержимое продолжает обновляться.
- Вариант окна полностью вне рабочего стола отвергнут: кадр не обновляется. Вариант с одним видимым краем отдаёт чёрные внеэкранные пиксели. Пользователь согласовал второй монитор.
- Тесты размеров поддерживают 3840×2160, 2160×3840 и уменьшение 8K. Сопоставление Qt/Windows проверяет физические координаты, перестановку экранов и масштабирование 150% на синтетических данных.
- Автоматические тесты проверяют владение кадрами, буфер без очереди, поток захвата, ошибки, закрытие и повторный запуск. Дополнительный тест воспроизводит отключение/перемещение второго монитора и проверяет безопасную остановку вывода.
- Исправлен запуск из каталога с пробелом; командный launcher использует `-m hdr_share`. Тест CLI проверяет кодировку cp1251.
- Финальный набор: 23 теста пройдены, compileall без ошибок; выполнена независимая проверка кода, исправлены обе существенные находки.
- Переносимая папка PyInstaller собрана. Обнаруженная несовместимая ICU из Poppler исключена: Qt загружает системную ICU Windows, как и при запуске из Python.
- Настоящий финальный exe запущен на 20 секунд и завершился с кодом 0: 1150 новых захваченных, 1129 отрисованных кадров за 19.75 секунды; средние частоты 58.23 / 57.16 FPS. Вывод 2560×1440, HDR→SDR активен, ошибок захвата нет. Эти показатели относятся к локальному окну, не к Discord.

## Не подтверждено

- Реальные 4K/60: оба доступных экрана 2560×1440. Наличие 4K в ограничениях размеров не является проверкой производительности 4K.
- Цветовая точность в конкретной HDR-игре, сохранение деталей светлых участков при разных калибровках HDR.
- Трансляция через Discord с просмотром на втором клиенте: проверен системный механизм захвата окна, а не полный путь Discord.
- Реальное горячее отключение монитора и DPI-перестройка оборудования: безопасное поведение проверено программными тестами.

Это рабочий прототип для дальнейшей проверки, не подтверждённая реализация всех требований 4K/60.
