# HDR Screen Share Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Native execution is recommended; the user must review this plan and select the execution approach before implementation.

**Goal:** Python-программа, которая захватывает выбранный HDR-монитор, преобразует HDR в SDR и предоставляет окно для трансляции в Discord с поддержкой до 4K UHD и целью 60 кадров/с.

**Architecture:** hdrcapture выполняет захват и GPU tone mapping в отдельном рабочем потоке. Ограниченный буфер хранит последний BGRA-кадр, а PySide6 показывает его в отдельном окне на втором мониторе. Пользователь согласовал второй монитор после неуспешной проверки полностью внеэкранного окна. Окно управления позволяет выбрать источник и монитор вывода, остановить и повторно запустить захват.

**Tech Stack:** Python 3.12 x64, PySide6, hdrcapture, NumPy, PyInstaller, pytest.

**Spec:** docs/superpowers/specs/2026-10-17-hdr-discord-design.md

## Global Constraints

- По умолчанию выбран основной HDR-монитор, иначе первый HDR-монитор, иначе основной SDR-монитор с явным статусом SDR; захват запускается автоматически.
- Вывод в исходном разрешении до 4K UHD (3840×2160) с сохранением пропорций, целевая частота 60 кадров/с. Для повёрнутого монитора границы 2160×3840. Меньший источник не увеличивать; учитывать физические пиксели при DPI-масштабировании.
- Список источников содержит имя, физическое разрешение и активный статус HDR/SDR/неизвестен; обрабатывать только выбранный монитор.
- Вывод целиком внутри второго монитора, отличного от источника; уменьшение из-за разрешения второго монитора явно показывать в интерфейсе. Без второго монитора — понятная ошибка.
- Цель 4K/60 относится к программе и проверяется отдельно от качества трансляции Discord. Не снижать разрешение скрыто.
- Постоянное название окна: «HDR Screen Share — Discord».
- Только изображение; HDR Windows и настройки Discord не изменяются.
- Захват создаётся, используется и закрывается в одном рабочем потоке.
- Использовать auto, не принудительный восьмибитный sdr.
- Нельзя применять WDA_EXCLUDEFROMCAPTURE к окну вывода.
- Отсутствие HDR-оборудования или второго клиента явно ограничивает проверку готовности.

## Review Focus

1. Неподходящий wheel или отсутствующий backend: понятная ошибка вместо запуска обычного SDR-захвата.
2. Порядок мониторов Qt и backend различается: статус HDR и выбор источника должны совпадать с реальными устройствами; основной SDR не вытесняет другой HDR-монитор.
3. Захват быстрее GUI: память не растёт, изображение не ссылается на освобождённый буфер.
4. Закрытие, ошибка или смена монитора во время захвата: поток и ресурсы освобождаются без зависания.
5. Discord не видит окно-копию или получает чёрные кадры: нельзя объявлять задачу решённой; результат проверки фиксируется. Внеэкранный вывод отвергнут реальным тестом, второй монитор согласован пользователем.

### Task 1: Проверить HDR backend и изоляцию кадров

**Interfaces:** `CaptureSource(id: str, label: str, primary: bool, hdr_enabled: bool | None, width: int, height: int)`, `list_sources() -> list[CaptureSource]`, `default_source(sources: list[CaptureSource]) -> CaptureSource`; `LatestFrame.put(frame: numpy.ndarray) -> None`, `LatestFrame.take() -> numpy.ndarray | None`; `fit_size(width: int, height: int) -> tuple[int, int]`.

- [ ] Проверить релиз hdrcapture v0.3.0: совместимый wheel win_amd64 для CPython 3.12/abi3, лицензию MIT, SHA-256 и зависимости. PyPI при предварительной проверке вернул 404; не рассчитывать на непроверенную команду установки. Создать локальную .venv, закрепить реально установленные версии и источник wheel.
- [ ] До реализации написать тесты: последний из двух кадров заменяет первый; изменение исходного массива не меняет сохранённый; пустой буфер возвращает None; `fit_size(3840,2160)==(3840,2160)`, `fit_size(7680,4320)==(3840,2160)`, `fit_size(2160,3840)==(2160,3840)`, `fit_size(1080,1920)==(1080,1920)`, `fit_size(1280,720)==(1280,720)`; неположительный размер вызывает ValueError. Проверить физические размеры 4K при DPI 150%, не подменяя их логическими 2560×1440.
- [ ] Запустить `python -m pytest tests/test_frames.py -q`, подтвердить ожидаемое падение из-за отсутствующей реализации. Реализовать буфер с одним слотом и копированием при передаче владения, расчёт размеров; повторить тесты до PASS.
- [ ] Изучить API и код перечисления мониторов hdrcapture, сопоставить устройства по идентичности/координатам с Windows, не по порядку Qt. Проверить импорт и один настоящий кадр auto; записать размер, формат и is_hdr, не сохранять содержимое экрана без необходимости.
- [ ] Если нет совместимого wheel или HDR backend не работает, остановить зависимую реализацию и сообщить конкретную причину. Зафиксировать работоспособный этап локальным коммитом.

### Task 2: Захват, окна и управление

**Interfaces:** `CaptureWorker(source_id: str, frames: LatestFrame)` с `run()`, `request_stop()`, сигналами состояния и ошибки; `OutputWindow.set_frame(frame: numpy.ndarray)`; `ControlWindow` владеет текущим worker и окном вывода.

- [ ] Написать тесты с поддельным backend: создание/чтение/закрытие в одном потоке; исключение закрывает сессию; остановка не оставляет работающий поток; переставленные мониторы сохраняют правильный выбор. Проверить два HDR-монитора, основной SDR с дополнительным HDR, отсутствие HDR, неизвестный HDR-статус и отключение выбранного монитора. Неизвестный статус не называть подтверждённым SDR или HDR. Запустить и подтвердить ожидаемое падение.
- [ ] Реализовать worker с ограничением до 60 кадров/с, слотом последнего кадра, ожиданием остановки и явным статусом отсутствия новых кадров. При смене источника завершать старый worker перед созданием нового. Проверить тесты до PASS.
- [ ] Написать Qt-тесты: запускается выбранный по HDR-приоритету источник; ошибка видна пользователю; повторный запуск после ошибки возможен; закрытие ждёт остановки; выходной QImage сохраняет данные после освобождения исходного кадра; окно вывода помещается во втором мониторе, не выбирает монитор источника и не увеличивает малые кадры. Сначала подтвердить FAIL, затем реализовать ui.py и точку входа.
- [ ] Добавить выбор монитора с именем/разрешением/HDR-статусом, «Запустить / Остановить», статус, счётчик фактических новых кадров/с и короткую инструкцию выбора окна в Discord. Переключение источника останавливает предыдущую сессию. GUI получает последний кадр таймером, без очереди сигналов с массивами. Ошибка изменения дисплея предлагает перезапуск, а не оставляет молча старую картинку.
- [ ] Запустить все тесты и настоящее приложение. Проверить остановку/перезапуск и изменение размера источника. Зафиксировать этап коммитом.
