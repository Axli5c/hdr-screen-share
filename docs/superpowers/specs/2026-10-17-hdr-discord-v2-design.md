# HDR Screen Share v2 — виртуальный вывод и звук

## Назначение и статус

Это описание заменяет способ вывода версии 0.1 из 2026-10-17-hdr-discord-design.md. Пользователь отверг полноразмерную копию на физическом втором мониторе. Новый результат: компактная миниатюра внутри приложения, самостоятельный источник в списке приложений/экранов Discord, HDR→SDR до 4K с целевой частотой 60 FPS, звук приложений без микрофона и звука Discord. Пользователь согласился с однократной установкой подписанных виртуальных драйверов.

Документ описывает проектируемую версию. Драйверы только загружены для проверки подписей в .scratch; не установлены. Новый маршрут звука, виртуальный вывод и 4K/60 ещё не проверены. Существующий exe остаётся прототипом 0.1 до сборки и проверки v2.

## Пользовательский сценарий

1. При первом запуске приложение проверяет драйвер виртуального дисплея и VB-CABLE. Для отсутствующего компонента показывает конкретный пакет, издателя и действие установки с повышением прав. Установка выполняется отдельно от обычного запуска и не повторяется при каждом старте.
2. Пользователь выбирает физический HDR-монитор. В окне управления отображаются миниатюра, статус HDR→SDR, состояние звука и фактическая частота кадров. Выбора физического монитора для копии больше нет.
3. На отдельном виртуальном SDR-дисплее открывается окно «HDR Screen Share — Discord» с полным изображением. Оно не показывается на физических мониторах и не получает фокус. В Discord пользователь выбирает это окно во вкладке приложений и включает передачу звука приложения.
4. Миниатюра — только предпросмотр, до 480×270 и 15 FPS. Размер миниатюры не ограничивает разрешение окна для Discord. При сворачивании управления предпросмотр приостанавливается, трансляционный вывод и звук продолжаются.
5. «Остановить» прекращает видео и аудио, закрывает окно вывода и освобождает выделенный виртуальный экран. Закрытие приложения выполняет ту же очистку.

Выбор именно окна программы нужен для привязки отфильтрованного звука к нашему процессу. Обычная трансляция целого виртуального экрана с опцией «весь системный звук» не удовлетворяет требованию исключить Discord и не является рекомендуемым сценарием v2. Обнаружение окна в установленной версии Discord и захват его звука с виртуального выхода — обязательная проверка до объявления версии готовой.

## Компоненты и стек

- Python 3.12 x64 и PySide6: управление, миниатюра, статусы, жизненный цикл.
- hdrcapture: существующий захват физического монитора с GPU-преобразованием HDR→SDR, режим auto. Его пригодность к устойчивым 4K/60 проверяется отдельно.
- Virtual Display Driver: подписанный готовый драйвер, управляемый через его доступный IPC и Windows DisplayConfig. Наше приложение не пишет собственный драйвер.
- Нативная библиотека audio_bridge.dll с C ABI, загружаемая в процесс приложения: WASAPI process loopback, перечисление звуковых сессий, фильтрация процессов, смешивание и воспроизведение на виртуальный выход. Python не обрабатывает каждый PCM-пакет в GUI-потоке.
- VB-CABLE: подписанный виртуальный аудиовыход для отфильтрованного потока. Не назначать его системным устройством по умолчанию или микрофоном Discord.
- PyInstaller onedir: переносимая папка приложения после однократной установки драйверов. MSVC нужен только разработчику для сборки audio_bridge.dll.

## Видео и виртуальный дисплей

Входной монитор сопоставляется по идентичности Windows и физической геометрии, а не порядку Qt. Собственный виртуальный экран исключается из списка входов. По умолчанию выбирается основной физический HDR-монитор, иначе первый физический HDR-монитор.

Режим виртуального экрана — SDR, 60 Гц, размер соответствует источнику с ограничением 3840×2160, для портретного источника 2160×3840. Меньший источник не увеличивается. Доступные режимы драйвера проверяются; если необходимого нет, выводить причину и предлагать явно выбрать меньший режим, без скрытого уменьшения до 1080p.

Окно вывода полностью находится внутри активного виртуального экрана; не использовать отвергнутый способ с окном вне всех дисплеев. Основное окно с миниатюрой исключается из захвата с помощью SetWindowDisplayAffinity только для его HWND. Окно для Discord не исключается. Это предотвращает повторный захват самой миниатюры, когда управление находится на исходном мониторе.

Приложение не меняет HDR, разрешение, основной монитор и размещение окон на физических дисплеях. Виртуальный монитор становится дополнительной частью рабочего стола Windows, поэтому абсолютную невидимость для других приложений обещать нельзя. Он используется только для вывода программы, не становится основным и отключается при остановке; его расположение и влияние на перемещение курсора проверяются на реальной конфигурации. Чужие виртуальные мониторы не отключаются. При невозможности отличить собственный экземпляр от чужого операция останавливается с объяснением.

Полные кадры не проходят через очередь миниатюр: независимые потребители используют последний доступный кадр, очереди ограничены. Внешнее изменение дисплеев или потеря собственного виртуального экрана сначала скрывает вывод и останавливает захват; затем предлагает обновить конфигурацию. Восстановление не перезаписывает изменения физических экранов, сделанные пользователем во время работы.

## Аудио без микрофона и Discord

Захватывать пользовательские приложения через WASAPI process loopback. Обычный смешанный loopback устройства без фильтрации не использовать: в нём уже может присутствовать Discord. Физические устройства записи не открывать; обычную настройку микрофона голосового чата Discord не изменять.

Перечислять активные render-сессии всех доступных устройств воспроизведения и обновлять набор источников при появлении/исчезновении сессий. Перед добавлением источника определить образ процесса, его время создания и дерево дочерних процессов. Исключить все экземпляры настольного Discord, включая PTB/Canary, и собственный процесс со всеми дочерними процессами. Это исключает голоса собеседников, звуки Discord и повторный захват собственного аудиовыхода. Discord в браузере не поддерживается как отдельная фильтруемая вкладка: Windows API различает процессы, а не вкладки; для этой версии требуется настольный Discord.

Process loopback захватывает дерево процесса, поэтому выбор источников должен быть непересекающимся: один и тот же дочерний процесс нельзя захватить и отдельно, и через родителя. Нельзя включать дерево, содержащее исключённый процесс. При невозможности построить полный безопасный набор источников остановить передачу аудио и показать причину; не подмешивать Discord и не заявлять, что весь разрешённый звук успешно захвачен. Смена PID после перезапуска Discord и повторное использование PID должны пересчитывать фильтр до подключения нового источника. Защищённые Windows/DRM-потоки, которые ОС не позволяет захватывать, не обходить и не выдавать за поддерживаемые.

Внутреннее смешивание — stereo float32, 48 kHz, с ограниченным буфером, временными метками и защитой от переполнения. Выход на playback-устройство VB-CABLE выполняется внутри того же процесса, которому принадлежит окно для Discord. Игра продолжает воспроизводиться на исходных наушниках/колонках; наша программа не проигрывает копию в физическое устройство и не меняет выходы других приложений. Виртуальный аудиовыход выбирается по endpoint ID, а не только локализованному имени.

Первый обязательный эксперимент реализации: два независимых тестовых источника, один разрешённый и один исключённый, дают на выходе только разрешённый сигнал; затем Discord должен получить этот поток при захвате окна программы с VB-CABLE. Наличие звука на виртуальном устройстве само по себе не доказывает звук в трансляции. Если Discord не захватывает такой аудиовыход процесса, остановить этот путь и согласовать другой способ доставки до дальнейшей переработки UI. Не заменять микрофон Discord виртуальным кабелем как незаметный обходной путь.

При ошибке фильтрации аудио автоматически заглушается, видео может продолжать работать с заметным статусом «звук отключён: причина». При переполнении буфера отбрасываются устаревшие данные, очередь не накапливается. Целевое рассогласование звука и изображения не более 80 мс, без дрейфа за 10 минут; это проверяемая цель, не подтверждённая характеристика.

Пакеты загружаются из первичных источников для конкретного пользователя и проверяются перед запуском. Условия VB-Audio не дают основания автоматически включать чужой установщик в распространяемый exe: в сборке хранить официальный URL, контрольную сумму и ссылку на лицензию; пакет не перепаковывать. При несовпадении хеша/подписи установку прекращать.

Установка требует отдельного повышения прав и конкретного проверенного действия. Не включать тестовый режим Windows, не отключать Secure Boot и не импортировать самоподписанные корневые сертификаты. Если стандартная установка проверенного пакета требует дополнительного изменения доверия, остановиться и объяснить требование до выполнения. Возможную перезагрузку показывать и не выполнять автоматически. Обычный запуск приложения работает без администратора; операции, требующие повышения прав, не маскируются под обычное включение трансляции.

## Порядок реализации и критерии

Сначала проверить соединение с виртуальным дисплеем и полный аудиомаршрут на небольших диагностических пробах, затем адаптировать UI и полноценный вывод. Это один проект с тремя зависимыми частями: управление устройствами → аудио/видео вывод → миниатюра и упаковка. Нельзя объявлять версию готовой по одному работающему предпросмотру.

Обязательные проверки:

1. Драйверы проходят подписи/хеши; после установки свои устройства определяются однозначно. Нет изменения основного физического экрана, его HDR и режимов, нет назначения VB-CABLE устройством по умолчанию.
2. На одном физическом мониторе приложение работает с собственной виртуальной целью; полноразмерных окон на физических экранах нет. Миниатюра не вызывает зеркального повторения.
3. Discord видит отдельное окно «HDR Screen Share — Discord»; второй клиент получает SDR-видео и отфильтрованный звук. Само окно предпросмотра не является источником полного потока.
4. Два разрешённых звуковых источника слышны ровно один раз. Исключённый тестовый процесс и настоящее дерево Discord отсутствуют. Микрофон не захватывается, обычная работа микрофона голосового чата сохранена. Перезапуск Discord не снимает фильтрацию.
5. Звук локально остаётся на прежних устройствах, копия не слышна второй раз. Добавление нового играющего приложения не требует перезапуска трансляции. Нет накопления очереди и дрейфа.
6. Остановка, закрытие, ошибка, изменение дисплеев и пропадание аудиоустройства очищают только собственные ресурсы. При повторном запуске нет лишних виртуальных дисплеев и зависших потоков.
7. Настоящие 3840×2160 SDR-кадры, после прогрева 60 секунд измерения: не менее 59 новых представленных кадров/с в среднем. Повторные перерисовки не считаются новыми кадрами. При недостижении цели сообщается фактическая частота; 4K/60 не маркируется подтверждённым.
8. Упакованный exe проверяется отдельно от запуска Python. Известное исключение чужой Poppler ICU в PyInstaller сохраняется.

Если нет доступа к просмотру вторым клиентом, критерий 3 остаётся невыполненным и выпуск маркируется диагностическим прототипом. Реальное включение трансляции людям не выполнять без указания пользователя.
